## 2. Cause

**Established from the code, plus an offline probe with the real classes:**
- **One shared bucket.** The main E2E backend (`127.0.0.1:8000`) ran the default `/api/v1` bucket: 10 per second, burst 20. It is keyed by client address (`app/main.py`, `app/api/admin.py`).
  - Both the dashboard's server-side reads and the tests' direct reads come from `127.0.0.1`, so they share that bucket.
  - The probe confirmed it: 20 requests at the same instant are accepted and the 21st is rejected.
- **Each navigation is a parallel burst:**

  | Page | Backend reads | Source |
  |---|---|---|
  | Overview | 5 (two to `/models/compare`) | `lib/server/overview.ts` |
  | Traces | 3 | `lib/server/traces.ts` |
  | Models | 3 | `lib/server/models.ts` |

  Navigations are not paced; only the direct reads are, at 150 ms.
- **A 429 replaces exactly the awaited elements:**
  - `components/overview/model-groups.tsx` renders `table-model-groups` only when `/models/compare` succeeded;
  - `app/traces/page.tsx` renders `ErrorState` instead of the list and its `next-page` link.
- **11:38:12** lists exactly the three reads of one Traces page load, the `goto("/traces?limit=10")` at `phase3c.spec.ts:294`. The click then waited until the 60 s test timeout, at 11:39:12.
- **11:40:17** is the 5 s expect timeout after the 11:40:12 429s.
  - Lines 327–329 of `phase8a6.spec.ts` passed, so `/overview` succeeded while `/models/compare` was rejected.
  - That partial success is what a nearly empty consuming bucket produces.
- **The auth-failure bucket is excluded.** It is 30 per minute, consulted before the token check, and can reject valid requests. But in the minute before either failure the only wrong-token traffic is one `phase6c.spec.ts` page load. Its rejections would also block every concurrent request, including `/overview`.

**Not established:**
- the backend's own reason code at 11:38 and 11:40 (`backend.log` was neither printed nor uploaded);
- the runner-speed difference between the two runs (no per-test durations were compared).

The difference is attributed to runner speed: same tree, configuration, worker count (1), retries (0) and test order.

## 3. Correction

**`scripts/qa/e2e_gate.sh`:**
- `readonly e2e_api_rps=1000 e2e_api_burst=1000`.
- `start_backend` exports `LLMI_RATE_LIMIT_API_RPS` and `LLMI_RATE_LIMIT_API_BURST` **inside the subshell that `exec`s the main backend**, so no other process receives them: not Playwright, the dashboards, or the `:8001`/`:8002` backends.
- `run_tests` passes `--backend-log "$state/backend.log"` to the report check.

**Why 1000/1000:**
- One worker loads one page at a time, so the suite's peak is far below 1000 requests per second, and 1000 tokens exceed any burst it can produce.
- The cap is still finite, so a request storm, such as a refresh loop, would fail the new check instead of passing silently.

**`scripts/qa/e2e_check.py` gains `check_backend_log`.** It is read fail-closed and only counted. The job fails on:
- **`BACKEND_LOG_MISSING`:** the log is missing or unreadable;
- **`BACKEND_LOG_EMPTY`:** the log is empty or blank;
- **`BACKEND_LOG_NO_STARTUP`:** it lacks either of uvicorn 0.54.0's lines `Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)` and `Application startup complete.`;
- **`BACKEND_RATE_LIMITED`:** any line contains a rate-limit rejection of `app/api/admin.py` or `app/services/ingestion/service.py`. The match is unanchored, so a log prefix cannot hide it:
  - `api rejected reason=api_rate_limited`;
  - `api rejected reason=authfail_rate_limited` / `ingest rejected reason=authfail_rate_limited`;
  - `ingest rejected reason=key_rate_limited`.

**How results are reported:**
- Authentication failures (`api auth failed reason=` / `ingest auth failed reason=`) are expected 401s. They are counted as `backend_auth_failed` and are never a problem.
- The totals of the sanitized summary record `backend_rate_limited` (0 on success) and `backend_auth_failed`.
- No log line is printed, annotated or uploaded, because the log holds request paths and client addresses.
- The failure detail is the count only.

**Unchanged:**
- **production:**
  - limiter code;
  - default limits (`config.py`: 10 / 20, ingest 20 / 40, auth failures 30 per minute);
  - the uvicorn logging setup;
- **tests and CI:**
  - every Playwright test, timeout and wait;
  - `retries: 0`;
  - the 429 tests on `:8001`/`:8002` (T43, 6C-C) with their 5- and 6-token buckets;
  - `.github/workflows/ci.yml`;
- **environment and data:**
  - `.env.example`;
  - every lock file.

- `npx playwright install --with-deps chromium` tried to apt-install Ubuntu packages, and both attempts reported `Temporary failure resolving 'azure.archive.ubuntu.com'`.

This is an infrastructure blocker before the suite, not a test failure. R133's rate-limit correction is therefore still **unverified on GitHub**.

### 9.2 Cause and evidence

- **What `--with-deps` installs.** It first runs `apt-get update` and `apt-get install` for Playwright 1.64.0's `ubuntu24.04-x64` lists (read from the installed `playwright-core` 1.64.0):
  - `chromium`: 21 shared-library packages;
  - `tools`: 12 packages, namely `xvfb`, nine font packages, `libfontconfig1` and `libfreetype6`.
- **Why it hung.** That apt step needs the Ubuntu mirror. When the runner cannot resolve it, the step hangs until the workflow timeout.
- **The browser download is separate.** `npx playwright install chromium` alone uses only Playwright's own CDN.
- **What the runner already has.** The `ubuntu-24.04` image (runner-images toolset and Readme, image 20261101.360.1, read 2026-11-11) preinstalls Google Chrome 156, Chromium 156, Microsoft Edge 156 and Firefox 159. Its explicit apt list names `xvfb` and `fonts-noto-color-emoji` but none of the 21 library packages, which most likely arrive as dependencies of those browsers.

  Whether every library package and font is present on the runner is **not established from documentation**. The gate now checks it on the runner itself (§9.3).
- **The binary the suite really launches.** Under Playwright 1.64.0, `npx playwright install chromium` installs `chromium-1248`, `chromium_headless_shell-1248` and `ffmpeg-1013`. Headless tests launch the **headless shell**, but the gate's existing `executablePath()` check only looked at the full Chromium binary.
- **Playwright's own host validation:**
  - it runs before a launch and throws an error naming the missing libraries or packages;
  - it is cached for 30 days by a `DEPENDENCIES_VALIDATED` marker;
  - it is skipped entirely when `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS` is set;
  - after a plain `install` it only warns.

### 9.3 Correction (`scripts/qa/e2e_gate.sh` frontend phase; no workflow change)

1. **Refusals before any work.** The phase refuses `PLAYWRIGHT_SKIP_*` (validation, browser download) and `PLAYWRIGHT_*DOWNLOAD_HOST*`.
2. **Browser only.** `npx playwright install --with-deps chromium` becomes `npx playwright install chromium`: the pinned browser, with no apt, no mirror and no `sudo`.
3. **Unchanged checks.** The version check (`Version 1.64.0`) and the `executablePath()` check stay as they were.
4. **Package check** (deterministic and offline):
   - `dpkg-query -W -f='${Package} ${db:Status-Status}\n'` runs over the 33 packages that `--with-deps` would install;
   - the list is printed by `e2e_check.py browser-packages` and pinned to Playwright 1.64.0;
   - it does not depend on apt lists.

   `e2e_check.py browser-deps` then evaluates the output:
   - **`BROWSER_HOST` (fail):** the host is not Ubuntu 24.04 x86_64 (`/etc/os-release`, `uname -m`).
   - **`BROWSER_DEPENDENCIES_UNVERIFIED` (fail):** `dpkg-query` exited with 2 or more, the output is unreadable or malformed, or a package is unexpected or omitted.
   - **`BROWSER_DEPENDENCIES_MISSING` (fail):** any of the 23 library packages (the 21 `chromium` packages plus `libfontconfig1` and `libfreetype6`) is not `installed`. The names are listed.
   - **`BROWSER_RENDERING_PACKAGES_MISSING` (named warning, not a failure):** any of the 10 font or `xvfb` packages is not installed. They only affect rendering, and `xvfb` is not used in headless runs. The names are listed.
5. **Launch check** (`scripts/qa/e2e_browser_smoke.mjs`, fail-closed). It:
   - refuses `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS`;
   - requires the frontend's own `@playwright/test` 1.64.0;
   - launches `chromium` exactly as the CI suite does: `{ headless: true }`, no channel, no `executablePath`, so Playwright's host validation and the headless shell are both exercised;
   - serves one page on an ephemeral `127.0.0.1` port, loads it and verifies a per-run token;
   - closes the browser.

   Failures are named, with sanitized single-line details. Missing system dependencies are listed by library or package name: `BROWSER_DEPENDENCIES_MISSING`, `BROWSER_LAUNCH`, `BROWSER_SMOKE`, `BROWSER_CLOSE`, `BROWSER_SMOKE_SETUP`, `BROWSER_VALIDATION_DISABLED`.

**Unchanged:**
- the workflow, including the step's `timeout 600`;
- the Playwright pin, `e2e-browser.ts` and `playwright.config.ts`;
- all 72 tests and their assertions;
- retries 0, workers 1;
- the rate-limit correction of §3.

Nothing is skipped or retried.

**Not changed, needs your decision.** Fonts are reported, not required. Earlier green runs had the full `--with-deps` font set, if apt succeeded. If the runner lacks some fonts, rendering differs from those runs, and an assertion that depends on text metrics could behave differently.

The warning names the missing packages in the job's annotations, so the effect is visible. To require them, move the ten names from `CHROMIUM_RENDERING_PACKAGES` to the required list. A missing font would then fail the job by name, and no apt mirror would be needed.
