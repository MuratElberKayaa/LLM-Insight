## 3. Implementation (Steps 3–7)

### 3.1 Trace Explorer — `/traces`
- Server component; one `GET /api/v1/traces` per render (`lib/server/traces.ts`).
- Columns: service + full trace ID (link), start (UTC, ms; ns in the title), duration (from `duration_ns`, BigInt), stored status (dot + text), spans, inference calls, tokens in/out (unknown stays "unknown", with the count of calls whose tokens are unknown), known cost (exact decimal; "unknown" when no row is priced, never `$0`; "N of M unpriced" when incomplete), prompt version, provenance badge. Below `md` the same values render as cards.
- Filters, all in the URL (`lib/trace-query.ts`): window presets 6 h / 24 h / 7 d / 31 d (UTC, aligned like the Overview) or a fixed `from`/`to` (≤ 31 days, ≤ 6 fraction digits); `status`; `provenance`; exact `model` (GET form, validated against the stored model-identifier format); page size 10/25/50/100. Unsupported values are ignored with a notice and never forwarded.
- Pagination: "Next page" carries the backend-echoed window (frozen) plus `next_cursor` and a display page number; "First page" keeps the window. A malformed cursor gives the 422 error state with a "start again" link.
- Empty, loading (`loading.tsx` skeleton), error (fixed copy per failure kind) states; filter navigation keeps the previous render dimmed (`aria-busy`) instead of flashing a skeleton.

### 3.2 Trace Detail — `/traces/{trace_id}`
- The id is opaque: it is only checked against the API format (32 lowercase hex) before a request; anything else shows "Not a valid trace ID" without echoing it or calling the backend. A 404 shows "Trace not found", explaining that a missing trace, another project's trace and a missing project are indistinguishable by design.
- **Provenance notice** for synthetic / mixed / unknown / real (real = "labeled real by the instrumentation", not verified).
- **Facts**: stored status, service, duration, span count (and "first N returned" when truncated), start/end with all nine fraction digits, inference calls and tokens, known cost, prompt version, provenance.
- **Status breakdown**: trace level (stored, `error` if any span is ERROR; R27 not reinterpreted), span failures split into inference attempts and application spans, and logical calls "recovered after a failed attempt" / "ended with a failed attempt". Recorded `error.type` is shown as reported; the page states that no cause is inferred.
- **Span tree and waterfall** (`components/traces/waterfall.tsx`, client): see §4.
- **Logical calls and retries**: attempts grouped by `llminsight.call_id`, in attempt order, each with status, `error.type` and duration; outcome `No failed attempt` / `Recovered after retry` / `All attempts failed` / `Last attempt failed` / `Attempt status not in response`; attempts without `call_id` are listed alone ("ungrouped").
- **Inference attempts** (usage ledger): span, attempt, status, provider, requested → response model, input/output/cached/reasoning tokens, cost (exact) or "unknown" + reason, price version, provenance.
- **Span table** (`<details>`): text alternative to the waterfall with tree order, ids, parent, position, kind, status, `error.type`, offset, duration, start (ns).
- No element suggests prompt or completion content; the page says it is not stored.

## 4. Span tree, waterfall and timestamp handling

- **Lossless transport.** `lib/json.ts` parses every backend body with the reviver's source text: an integer above 2^53 becomes `LosslessInt` with its exact digits (e.g. `gen_ai.request.seed = 4611686018427387905` displays exactly); decoders that need a plain number reject it, so nothing is silently rounded. Token counts are decoded to digit strings (`bigCount`).
- **Nanoseconds.** `*_unix_nano` / `duration_ns` stay strings and are compared and subtracted as BigInt (`lib/nanos.ts`). Timestamps are printed from the backend's ISO strings by string handling (no `Date`, which keeps only milliseconds). Offsets and durations are exact (`+1.000001 ms`, `25.000017 ms`); digits are truncated, never rounded up.
- **Geometry.** Bar left/width = BigInt ratio of the trace axis (stored trace start → end) at 0.0001 % resolution; a zero-length axis or span cannot divide by zero (2 px minimum bar).
- **Hierarchy** (`lib/span-tree.ts`): built from `parent_span_id` among returned spans; siblings and top-level spans ordered by (start ns, span id) — the backend's own order — so equal start times always render the same way. Top level holds roots, orphans (`role=orphan`), spans whose parent was cut by the 2000-span limit, and spans unreachable from any root (a client-made parent cycle); each non-root top-level row is labeled. Iterative walk with a visited set: no recursion limit (1500-deep chain tested), no infinite loop on cycles. Missing timing is never inferred.
- **Waterfall UI.** WAI-ARIA tree (`role=tree/treeitem`, `aria-level`, `aria-setsize`, `aria-posinset`, `aria-expanded`, `aria-selected`, one roving tab stop): ↑/↓ move, Home/End, → expands or enters, ← collapses or goes to the parent, Enter/Space toggles. Selection follows focus and is written to `?span=` (`history.replaceState`) so it is shareable. A selected-span panel shows ids, position, kind, status and recorded `error.type`, offset, duration, ns start/end, the usage row (provider, models, attempt, call id, response id, five token fields, usage source, exact cost or unknown + reason, price version, call-key source), allowlisted span and resource attributes, scope, dropped-attribute count and attribute map. Rows render 200 at a time ("Show 200 more").
- **Encoding.** Gray = application span, blue (`series-1`) = inference attempt, red = status ERROR, always with a ✕ glyph and text, plus an "LLM · attempt n" tag and a "synthetic" tag per row; legend shown. Validated with the dataviz `validate_palette.js` on the dark surface `#15171c`: CVD all-pairs worst ΔE 8.5 (deutan), normal-vision worst ΔE 17.5, contrast ≥ 3:1. The gray fails the chroma floor by design (it is the de-emphasis tone, not a categorical hue). No new charting dependency (plain HTML/CSS bars).
